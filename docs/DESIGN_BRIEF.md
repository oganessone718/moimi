## 1. 제품 한 줄 & 브랜드

**모이미 (moimi)** — "언제 + 어디서"를 한 번에 정하는, 가입 없이 카톡으로 쓰는 모임 약속 서비스.

> ⚠️ **네이밍 미확정 (작업명).** "모이미"는 모이다(gather)에서 온 작업용 이름. 후보·논의 이력은 `docs/DECISIONS.md` §네이밍 참고. 워드마크는 시안 여러 개로 받아볼 것.

- **이름 유래(작업명)**: 모이다(gather/모임) + 친근한 "-미" → 마스코트형 코인드 네임. 고유성↑(검색·도메인 충돌 적음).
- **태그라인 후보**: "약속, 모이미에서 한 번에" / "모여서 정하지 말고, 모이미로"
- **로고 방향**: 둥근 산세리프 워드마크 + 지도핀/말풍선 모티프, 마스코트 캐릭터 가능성. 이모지스럽고 친근하게. (확정 아님 — 시안 여러 개)

## 2. 타겟 사용자 & 사용 맥락 (디자이너가 반드시 알아야 할 것)

| 항목 | 내용 | 디자인 함의 |
|------|------|-------------|
| 누가 | 친구·소모임·동아리, 20~30대 한국 사용자 | 친근·가벼운 톤, 격식 X |
| 어떻게 들어옴 | **대부분 카톡 링크 → 모바일 인앱 브라우저** | **모바일 우선 절대 원칙**, 세로 한 손 조작 |
| 핵심 행동 | 가입 없이 닉네임만 적고 → 날짜/시간/장소 투표 → 제출 | 진입 마찰 0, 닉네임 입력이 첫 화면 |
| 주최자 | 폴 만들고 카톡에 뿌리고 결과 확정 | 공유 버튼이 가장 눈에 띄어야 |
| 감정 | "또 일정 조율이야?"의 피로 → "오 이거 편하네"로 | 빠르고 경쾌한 피드백, 작은 즐거움 |

## 3. 비주얼 톤: 캐주얼·플레이풀

### 무드
밝고 둥글고 친근하게. "약속 잡기는 귀찮은 일"을 **가볍고 즐겁게** 만든다. 딱딱한 엔터프라이즈 느낌 금지. 토스/두들/노션 캘린더의 친근함 + 약간의 장난기.

### 컬러 (제안 — 시안에서 조정 가능)
- **메인**: 따뜻하고 경쾌한 1색 (예: 코랄/탠저린 `#FF7A59` 또는 프레시 그린 `#34D399`) — "만나" 핀/CTA에 사용
- **서브**: 부드러운 보조색 1~2개 (라벤더/스카이)
- **YES/MAYBE/NO 투표 컬러**: 초록 / 노랑 / 회색 (신호등 직관)
- **배경**: 거의 화이트 + 아주 옅은 웜그레이, 카드에 부드러운 그림자
- 다크모드: v1.1 (MVP는 라이트 우선)

### 타이포
- 한글 우선 가독성 (Pretendard 권장). 제목은 두툼하고 둥근 느낌, 본문은 깔끔하게.
- 큰 제목 + 충분한 행간으로 모바일에서 시원하게.

### 형태·질감
- **둥근 모서리** (radius 12~20px), 둥근 버튼, pill 형태 칩
- 부드러운 그림자, 약간의 입체감
- **이모지·미니 일러스트** 적극 활용 (📍🗓️🙌🎉), 빈 화면(empty state)에 귀여운 일러스트
- 색면 대비로 위계 표현

### 마이크로 인터랙션 (플레이풀의 핵심)
- 투표 탭 시 살짝 통통 튀는 애니메이션
- 제출 완료 시 컨페티/체크 애니메이션 🎉
- 후보가 1위로 올라설 때 부드러운 순위 이동
- 로딩은 지루하지 않게 (귀여운 스피너/스켈레톤)

## 4. 디자인 원칙 (불변 규칙)

1. **모바일 우선 (Mobile-First)** — 모든 화면은 360~390px 세로 화면에서 먼저 완성. 데스크탑은 확장.
2. **무가입 우선** — 게스트 플로우에 "로그인" 강요 절대 금지. 로그인은 구석의 선택 버튼.
3. **한 손 조작** — 주요 액션(투표/제출/공유)은 엄지가 닿는 하단에.
4. **3탭 안에 끝** — 링크 클릭 → 닉네임 → 투표 → 제출. 단계 최소화.
5. **공유가 주인공** — 주최자 화면에서 카톡 공유 버튼은 가장 크고 눈에 띄게.
6. **명확한 상태** — 진행중/마감/확정 상태가 한눈에. 내 응답 여부도.
7. **카톡 인앱 브라우저 안전** — 복잡한 스크롤 잠금·과한 JS 애니 자제, 작은 화면·노치 고려.

## 5. 반응형 요구사항

| 브레이크포인트 | 폭 | 레이아웃 |
|---------------|-----|----------|
| Mobile (기준) | ~390px | 1컬럼, 하단 고정 액션바, 풀폭 카드 |
| Tablet | 768px~ | 1~2컬럼, 사이드 여백 |
| Desktop | 1024px~ | 2컬럼(좌: 폴 정보/투표, 우: 지도/집계), 최대폭 컨테이너 |

- 지도는 모바일에서 접었다 펼치기(또는 탭 전환), 데스크탑에선 우측 상시 노출.
- 터치 타겟 최소 44×44px. 폼 입력은 모바일 키보드 고려.

## 6. 핵심 화면 & 화면별 스펙

> ★ = MVP 필수 화면. 각 화면은 모바일 프레임 기준으로 기술.

### 6.1 ★ 랜딩 (`/`)
- 히어로: 한 줄 가치 제안 + "약속 만들기" 큰 CTA(무가입 강조: "가입 없이 바로")
- 3컷 설명: ①날짜+장소 한번에 ②링크로 카톡 공유 ③모두 투표 → 확정
- 하단 살짝: "이미 받은 링크가 있나요?" / 구석에 로그인
- 톤: 일러스트 1~2개, 경쾌

### 6.2 ★ 폴 생성 위저드 (`/meetings/new`) — 스텝형
1. **기본 정보**: 제목(예: "이번 주 모임 🍻"), 모임 유형 선택(날짜만 / 장소만 / 날짜+장소) — 큰 카드 선택 UI
2. **날짜/시간 후보**: 달력에서 날짜 다중 선택. (옵션) "시간도 정하기" 토글 → 시간 범위
3. **장소 후보**: 장소 추가(이름/링크 붙여넣기 → 자동 카드화), 지도에서 위치. "참가자도 추가 가능" 토글
4. **옵션 & 관리자 PIN**: 마감일, 익명투표 토글, **관리자 PIN 설정(무가입 시 필수)**
5. **완료 → 공유**: 생성된 링크 + **큰 카톡 공유 버튼** + 링크 복사. "관리 PIN을 기억하세요" 안내
- 진행 표시(스텝 인디케이터), 뒤로/다음 하단 고정

### 6.3 ★ 게스트 응답 (`/m/[shareToken]`) — 가장 중요한 화면
- **첫 진입**: 모임 제목 + 닉네임 입력(+선택 PIN "내 응답 보호") → "참여하기". 로그인 요구 X
- **탭 구조** (또는 세로 스택): [날짜] [장소] [내 응답]
  - **날짜/시간 투표**: 후보 날짜 카드마다 YES🟢 / MAYBE🟡 / NO⚪ 탭. 시간 옵션이면 "가능 시간대" 선택. 모바일에서 탭으로 빠르게.
  - **장소 투표**: 장소 카드(썸네일/이모지/이름/거리) + 좋아요 하트. 지도 보기 토글로 마커 한눈에. (옵션) "내 출발지 입력"
  - **내 응답**: 내가 고른 것 요약, 수정 가능
- **하단 고정**: "제출하기" 버튼. 제출 시 🎉 애니메이션
- 미제출/제출 상태 뱃지

### 6.4 ★ 결과/집계 화면 (게스트·주최자 공용 뷰)
- **날짜 히트맵**: 후보별 YES/MAYBE/NO 막대 또는 히트맵, 1위 하이라이트
- **장소 랭킹**: 좋아요 순 카드 리스트 + 지도 마커
- 참가자 수/제출 현황(예: 5명 중 3명 제출)
- (있으면) **중간지점 추천**: 출발지들 평균 위치 + 주변 추천 장소 핀 — 부가기능, 출발지 입력자 있을 때만

### 6.5 ★ 주최자 관리 (같은 모임 URL + 관리 모드)
- 진입: "관리자" 버튼 → **PIN 입력**(또는 로그인) → 관리 모드 전환
- 관리 액션: 후보 추가/삭제, 마감(투표 잠금), **최종 날짜·장소 확정**
- 확정 시: 확정 카드 미리보기 → 확정 → 모두에게 보이는 확정 상태로

### 6.6 ★ 확정 결과 화면
- "📍 OO에서 / 🗓️ O월 O일 O시 / 만나요!" 큰 확정 카드
- 카톡으로 확정 공유 버튼, (v1.1) 캘린더 추가/ICS
- 축하 톤 (컨페티)

### 6.7 카톡 공유 카드 미리보기 (디자인 필요)
- 카카오 공유 시 뜨는 카드(썸네일/제목/설명/버튼)의 비주얼. 브랜드 일관성.
- 자동 멘트 예: "[제목] 일정 정해요! 👇 투표해주세요"

### 6.8 내 모임 대시보드 (`/me`) — 로그인 시 (S9, MVP 후반)
- 내가 만든/참여한 모임 리스트, 상태별, 빠른 진입
- 비로그인 유도 배너: "로그인하면 내 모임이 여기 모여요"

### 6.9 공통 상태 화면
- 빈 상태(empty), 로딩 스켈레톤, 에러, 마감된 모임, 잘못된 링크 — 모두 귀여운 일러스트 + 명확한 안내

## 7. 핵심 컴포넌트 (디자인 시스템 요청)

디자인 시 아래 컴포넌트를 **재사용 가능한 시스템**으로 만들어 달라:
- **버튼**: Primary(채움)/Secondary(외곽)/Ghost, 크기 3종, 둥근 형태. 하단 고정 액션바용 풀폭 버튼.
- **투표 셀**: YES/MAYBE/NO 3-state 토글 (색·아이콘으로 구분, 탭 애니)
- **날짜/시간 후보 카드**, **시간대 선택 UI**(가능 시간 범위)
- **장소 카드**: 썸네일/이모지·이름·거리·좋아요·댓글수
- **지도 + 마커**(카카오맵 스타일), **중간지점 핀**
- **닉네임 칩 / 아바타**(이니셜·색), **참가자 목록**
- **PIN 입력**(4~6칸), **공유 버튼**(카톡 노란색 규격 고려)
- **상태 뱃지**(진행중/마감/확정), **토스트/스낵바**, **스텝 인디케이터**
- **빈 상태 일러스트 세트**

---

## 8. 제약 & 접근성

- **카톡 인앱 브라우저**: 과한 풀스크린·스크롤 하이재킹 금지. 안전영역(safe-area) 패딩. 외부 브라우저 열기 안내가 필요할 수 있음.
- 색만으로 정보 전달 금지(투표는 색+아이콘+텍스트 병행) — 색약 배려.
- 명도 대비 WCAG AA. 폰트 최소 14px(본문 16px 권장).
- 로딩/네트워크 느릴 때 스켈레톤. 한국어 기준 줄바꿈·말줄임.

## 9. Claude에게 줄 프롬프트 예시 (복붙용)

### 전체 시작
```
첨부한 모이미 디자인 브리프를 기준으로 모바일 우선 반응형 UI를 디자인해줘.
톤은 캐주얼·플레이풀, 한국어 서비스야. 먼저 핵심 화면인 "게스트 응답 화면(6.3)"부터
모바일(390px) 프레임으로 만들어줘. YES/MAYBE/NO 투표와 장소 카드, 하단 제출 버튼 포함.
```

### 화면별 (반복)
```
이번엔 "폴 생성 위저드(6.2)"를 디자인해줘. 5스텝, 스텝 인디케이터, 하단 고정 다음 버튼.
브리프의 컬러/둥근 형태/이모지 톤을 유지하고 모바일 우선으로.
```

### 디자인 시스템
```
브리프 §7의 컴포넌트들을 하나의 디자인 시스템 시트로 정리해줘.
버튼/투표 셀/장소 카드/PIN/뱃지/공유 버튼을 상태별로 보여줘.
```

### 반응형 확장
```
방금 만든 게스트 응답 화면을 데스크탑(1024px)으로 확장해줘.
좌측 투표, 우측 지도/집계 2컬럼 레이아웃으로.
```

## 10. 우선순위 (디자인 진행 순서 권장)

1. **디자인 시스템 기초** (컬러/타이포/버튼/카드) — 일관성 토대
2. **게스트 응답 화면 (6.3)** — 가장 많이 보이고 전환을 좌우
3. **폴 생성 위저드 (6.2)** + **공유 화면**
4. **결과/집계 (6.4)** + **확정 결과 (6.6)**
5. **주최자 관리 (6.5)**, **랜딩 (6.1)**
6. 대시보드(6.8)·공통 상태(6.9)·카톡 카드(6.7)

> MVP 디자인은 1~5번까지. 6번은 여력 될 때.
