# 화면 구현 프롬프트 세트 (Claude Design용)

> 사용법: **디자인 시스템을 만든 그 대화에서 이어서** 화면을 시키거나, 새 대화면
> 디자인 시스템이 뱉은 **CSS 변수 토큰 블록을 맨 위에 붙여넣고** 시작한다.
> 우선순위 순서대로 진행 권장 (브리프 §10). 화면 번호는 `docs/DESIGN_BRIEF.md` §6 기준.

---

## 0) 공통 프리앰블 (매 화면 앞에 한 번 붙이기)

```
지금부터 모이미의 실제 화면들을 구현할 거야. 규칙:
- 방금 만든 디자인 시스템의 토큰(컬러/타이포/스페이싱/radius/그림자)과 컴포넌트
  (버튼/투표 셀/장소 카드/PIN/뱃지/공유 버튼 등)를 그대로 재사용해. 새로 만들지 말고 일관되게.
- 모바일 우선(390px). 만든 뒤 데스크탑(1024px) 버전도 이어서 보여줘.
- 캐주얼·플레이풀 톤, 한국어, 라이트 모드. 카톡 인앱 브라우저 고려(safe-area, 과한 스크롤 잠금 금지).
- 실제처럼 보이게 더미 데이터를 채워. 주요 액션은 하단 고정. 색만으로 정보 전달 금지.
- React + Tailwind(또는 CSS 변수) 단일 아티팩트로. 인터랙션(투표 탭, 제출 🎉)도 동작하게.
```

## 1) 게스트 응답 화면 (최우선, 브리프 6.3)

```
"게스트 응답 화면"(/m/[shareToken])을 구현해줘.
- 첫 진입: 모임 제목 + 닉네임 입력(+선택 PIN "내 응답 보호") + "참여하기". 로그인 요구 절대 금지.
- 참여 후 탭/스택: [날짜] [장소] [내 응답]
  · 날짜: 후보 날짜 카드마다 YES🟢/MAYBE🟡/NO⚪ 3-state 토글(색+아이콘+텍스트). 탭 시 통통 애니.
  · 장소: 장소 카드(썸네일/이모지·이름·거리·좋아요 하트) 리스트 + "지도 보기" 토글(마커). (옵션)"내 출발지 입력".
  · 내 응답: 내가 고른 것 요약+수정.
- 하단 고정 "제출하기" → 제출 시 🎉 컨페티, 제출 상태 뱃지.
더미 데이터로 5개 날짜 후보, 3개 장소 후보 채워줘.
```

## 2) 폴 생성 위저드 + 공유 완료 (브리프 6.2)

```
"폴 생성 위저드"(/meetings/new)를 5스텝으로 구현해줘. 상단 스텝 인디케이터, 하단 고정 뒤로/다음.
1) 기본 정보: 제목 입력 + 모임 유형 카드 선택(날짜만/장소만/날짜+장소)
2) 날짜/시간 후보: 달력 다중 선택 + "시간도 정하기" 토글→시간 범위
3) 장소 후보: 장소 추가(이름/링크 붙여넣기→카드화) + 지도 위치 + "참가자도 추가 가능" 토글
4) 옵션 & 관리자 PIN: 마감일, 익명투표 토글, 관리자 PIN 설정(필수)
5) 완료→공유: 생성된 링크 + 큰 카톡 공유 버튼 + 링크 복사 + "관리 PIN 기억하세요" 안내
마지막 공유 화면을 특히 경쾌하게(완료 축하 톤).
```

## 3) 결과·집계 + 확정 화면 (브리프 6.4 + 6.6)

```
"결과/집계 화면"과 "확정 결과 화면"을 구현해줘.
[집계] 날짜 히트맵(후보별 YES/MAYBE/NO 막대, 1위 하이라이트) + 장소 좋아요 랭킹 카드 + 지도 마커,
       참가 현황(예: 5명 중 3명 제출). 출발지 입력자 있으면 중간지점 추천 핀 섹션(부가).
[확정] "📍OO에서 / 🗓️O월 O일 O시 / 만나요!" 큰 확정 카드 + 카톡 공유 버튼 + 컨페티 축하 톤.
더미 데이터로 사실적으로 채워줘.
```

## 4) 주최자 관리 모드 (브리프 6.5)

```
"주최자 관리 모드"를 구현해줘. 같은 모임 URL에서 "관리자" 버튼 → PIN 입력(또는 로그인) → 관리 모드 전환.
관리 모드: 후보 추가/삭제, 마감(투표 잠금) 토글, 최종 날짜·장소 "확정" 액션(확정 전 미리보기).
일반 보기와 관리 모드의 차이가 분명히 보이게(관리 배지/액션 영역).
```

## 5) 랜딩 (브리프 6.1)

```
"랜딩 페이지"(/)를 구현해줘.
히어로: 한 줄 가치 제안 + "약속 만들기" 큰 CTA("가입 없이 바로" 강조).
3컷 설명: ①날짜+장소 한번에 ②링크로 카톡 공유 ③모두 투표→확정. 일러스트 1~2개로 경쾌하게.
하단: "이미 받은 링크가 있나요?" + 구석에 작은 로그인. 모바일/데스크탑 둘 다.
```

## 진행 팁
- 1번(게스트 응답)부터 하나씩, 결과 보고 "투표 셀만 더 크게" 식 부분 반복으로 다듬기.
- 빈 상태/로딩/에러(브리프 6.9)는 각 화면 끝나고 "이 화면의 빈 상태/마감된 버전도 보여줘"로 덧붙이기.
- 화면 디자인이 확정되면 → 산출된 마크업/토큰을 구현 단계(S2~)에서 실제 컴포넌트로 옮긴다.
